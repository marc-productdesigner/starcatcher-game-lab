Code cheat sheet
say("Hi!")
The computer talks. It shows up in the speech box.
background("skyblue")
Paints the whole stage one color.
circle(x, y, size, "gold")
A circle. x and y are the middle, size is how far it reaches from the middle.
box(x, y, width, height, "red")
A rectangle. x and y are the top-left corner.
emoji("🚀", x, y, size)
Draws a picture from the emoji keyboard, centered on x and y.
write("Score", x, y, size, "white")
Writes words. x is the left edge.
onFrame(() => { ... })
Runs the code inside about 60 times every second.
keyDown("left")
True while the key is held. Also "right", "up", "down" and "space". A, D, W and S work too.
random(1, 6)
A surprise whole number between the two numbers.
distance(x1, y1, x2, y2)
How far apart two spots are.
beep(440)
Plays a note. Try 200 for low, 440 for middle, 880 for high.
stopGame()
Freezes the game. Press Run to start again.
width and height
The stage size: 480 across and 320 down.
Colors
Use names like "tomato", "gold", "limegreen", "skyblue", "midnightblue", "hotpink", or codes like "#ff66cc".

For grown-ups

The plan

Your child learns real JavaScript by building one game, step by step. The last level is a finished star-catching game that they have taken apart, understood and remixed.

Everything runs on this page. Nothing is installed, nothing is uploaded and no account is needed.

At a glance

  • 11 levels, about 5 hours in total. The last level is open-ended and can run as long as she likes.
  • Two or three short sessions a week, 20 to 30 minutes each. One level per sitting is plenty.
  • Best on a laptop. On a tablet, the symbol buttons under the editor and the on-screen arrows under the stage make it workable.
  • Saved on this device. Her stars and her code live in this browser. Clearing the browser's site data erases them.
  • A session shape that works: 5 minutes to run last time's game, 15 minutes on the new level, 5 minutes of free tinkering.

How to sit with her

The aim is a kid who is comfortable changing code and seeing what happens. You do not need to know how to code.

Predict, then run

Before she presses Run, ask what she thinks will happen. Being wrong is useful information, not a failure.

Change one thing

Invite her to change one number and watch what moves. Silly numbers are encouraged.

Ask, don't tell

When something breaks: What did you expect? What happened instead? What is different between the two?

Let the bug speak

Error messages are written in plain words and point to the line. Most bugs are a missing quote, a missing bracket, or a capital letter.

Hints before answers

Each level has hints, then a peek at one possible answer. There is no penalty for using them.

Praise the process

Notice when she tries something new, reads an error, or fixes her own typo. Those habits matter more than finishing fast.

If something is not working

  • Arrow keys do nothing. Press Run, then click once on the stage. On a tablet, use the on-screen buttons under the stage.
  • No sound. Check that Sound is ticked under the stage. Some tablets mute web pages when the silent switch is on.
  • The code is a mess. Ctrl+Z (Cmd+Z on a Mac) undoes changes in the editor. Start over brings back the starting code for that level.
  • It seems frozen. Press Stop. A loop that never ends cannot hurt anything, and the page will tell her what happened.
  • Typing is hard on a tablet. The symbol buttons add brackets, quotes and operators in one tap, and Enter keeps her indentation.

After level 11

  • Let her design a second game with the same tools: a runner, a maze, a pet that she feeds.
  • If she likes making animations and stories, a block-based tool like Scratch is a gentle next stop. What she learned here (variables, loops, if, input) works the same way there.
  • When she wants more, Python or a real web page are good next languages. The big ideas carry over to nearly every language.
